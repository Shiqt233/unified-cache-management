# 场景功能

## 基本能力
KV Client支持如下功能
（1）根据IO结果更新连接状态（错误处理方案区分故障场景）
（2）使用探针检测并更新连接状态
（3）重试控制：
    a) IO失败或超时：支持重试IO；支持配置IO超时时间、IO重试次数
    b) 断链：支持IO失败或超时或探测异常后断链重连管理；支持配置重连频率
（4）实时统计IO流量并执行流量控制（先不要考虑实时统计IO流量）

## 触发事件
KV Client下方IO结果为失败（网络问题、盘问题、IO超时均可能下发失败）
定时探针检测链路联通性
KV Client下发IO并发大于阈值

## 主成功场景：
KV Client下发IO结果为失败，触发IO重试，输出日志。若IO重试仍失败，触发连接断连，连接标记为不可用，并更换其他可用连接进行重发，输出日志
KV Client依据探针结果保持连接或断开连接，断连连接场景会标记连接不可用，并输出日志
KV Client恢复建连线程执行成功，输出日志，后续对该连接IO可成功执行
KV Client下发IO并发大于阈值，触发流控，IO下发暂停直到IO流量低于预期值
按失败场景，如网络错误，超时错误，IO读写内容失败等区分错误码

## 扩展场景（包括异常场景）
KV Client恢复建连线程尝试建连时失败，连接保持断开状态
KV Client探针执行失败，保持当前所有连接状态

# 特性初步分析
KV Client连接管理负责管理用于数据传输任务的连接，在请求发起时根据负载选择一个合适的连接进行IO下发。并通过IO请求结果、周期性探针结果，周期性处理异常链接。注：链接指的是qp粒度的链接

## 选路策略及状态流转
### 策略
单个链接的状态分为：正常（上线，可接新流量）、自然排空（下线，不接新流量）
KV Client启动初始化时，根据上层传递的ip，port列表和qp数量，逐个建立链接，状态初始为正常
请求IO时，根据选择策略（最小负载或轮询）选择一个状态为正常的链接进行发送。如果没有可用链接，本请求置为失败
IO结束时：
    （1）失败的消息，按链接累加失败条数。（网络、硬件层错误）
    （2）成功的消息：连续失败条数归零
如果某个链接的连续失败条数超过阈值，进入排空状态

链接选择策略：
（1）最小负载（尚未处理完的请求数最少）：优先选择第一个负载为0的链接，否则选择负载最小的
（2）轮询：从上次选择继续，选择第一个不超负载限制的链接

链接管理线程：
    主要负责异常链接的重连，周期性对排空的链接进行重连和更新，上线。重连耗时长，代价高，因此不放在IO线程内

### 可配参数
（1）qp数量
（2）单qp最大负载
（3）连续失败x条后进入排空状态
（4）链接管理线程的处理周期
（5）链接选择策略

## IO链路探测
### 基本功能
目的：自动探测IO链路状态，识别异常并处理
旁路IO探针线程：周期性轮询所有“一个周期内无IO”链接发送keep alive请求，探测当前链路是否通畅，IO最多重试m次
重试退避：毫秒级短退避间隔
返回结果及处理方式：
（1）正常：不处理（连接本身就在可用连接池内，无需处理）
（2）异常：标记异常（进入自然排空状态，连接管理线程会周期性重连

隔离必要性分析：探针数据会在业务数据所在链接管道内发送，可能对业务链路产生干扰。但如果单独新建连接，与业务隔离开，无法起到探测链路的目录。所以，选择在原channel+无IO时发起探测

### 可配参数
（1）探针线程的探测周期
（2）单探测周期内，探针最多重试m次和重试退避间隔

## 重试和重连
### IO异常种类
a 数据内容异常（写时key存在，写超长等）
b 盘框超负载，返busy
c 盘/网络等有故障
d 其他未知情况

### 单链接各阶段处理策略
（1）启动初始化，建链失败或超时：重试K次。仍失败，则视为初始化失败，向上层直接透传失败
（2）运行时：
    a 链接管理线程：处理建链失败或超时：重试K次。仍失败，继续标记链接异常，下一周期重试
        重试退避：重连失败后，拉长下次重试间隔。避免故障恢复期间，高频重连打爆下游
    b IO线程发送数据失败，按照返回错误码区分
        i）数据内容异常（写超长，写时key已存在，查时key不存在）；应用层错误，不重试，不标记异常，直接返错
        ii）busy：原链接重试，最多重试M次。该场景不标记链接异常（触发流控）。重试退避：毫秒级短退避间隔
        iii）盘/网络等有故障或其他，标记链接异常，换链重发。换链最多重试N次
    c IO线程发送数据超时：标记链接异常，换链重发。换链最多重试N次
（3）其他：默认标记异常，换链最多重试N次

### Batch请求处理策略
上述是对单条链接的处理。batch请求会根据batch size上限，拆分subBatch，分批发送
单个subBatch内存在部分失败或全部失败：
    如果1种错误码，单条异常重试
    否则整个subBatch换链重试N次
    Batch仅做返回结果的汇总，不进行二次处理

### 存储节点故障可用性分析
若某个节点完全故障，随IO发送失败，所以qp链接逐个进入排空状态，不接受新流量。新请求无可用链接而立即失败。链接管理线程一个周期内重连所以链接均失败后，标记该节点不可用。其他组件通过接口查询到当前节点状态

状态码：GREEN（全部可用），YELLOW（部分可用），RED（完全不可用）

### 可配参数
（1）建链超时时间
（2）单次IO超时时间
（3）busy下，原链路重试次数M
（4）换链重试次数N
（5）建链异常重试次数K
（6）重连退避间隔
（7）重试退避间隔

## 链路流量管理
### 基本功能
目的：下游繁忙出现busy情况时，反压上游进行限流
限流机制：拥塞控制算法，快降慢升。可配置单qp链接的“忙时最高负载阈值”为T。当下游出现busy时，触发流控，阈值T立即生效。单个ip：port下所有qp队列都会被限流。规则时：
当前实际负载 < 阈值T，新IO仍可继续请求
若当前实际负载 >= 阈值T，新IO不可进入，持续等待，直到负载低于阈值T

动态解除限流：
    每收到一个成功subBatch响应（不含探针），阈值+=1，每收到一个busy响应，阈值-=2
    动态阈值的取值不低于“忙时限流阈值T”，不超过“单qp最大负载”。当动态阈值达到“单qp最大负载”或持续成功响应X分钟后，解除限流机制（仍不能超过“单qp最大负载”）

### 可配参数
（1）限流并发处理请求数阈值T（T的取值低于常态水位）
（2）解除限流需要持续稳定X分钟
