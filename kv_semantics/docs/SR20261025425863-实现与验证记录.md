## 3. 关键链路验证

| 链路 | 入口与步骤顺序 | 前置状态 | 最终可观察结果 |
|---|---|---|---|
| L01 busy 重试 | Transport Submit → 首次 busy → 原 Channel 新 CID 重试 M 次 → Poll 最终响应 | ACTIVE Channel、可用 Slot/Flag | 同一 handle，多次不同 CID，最终有效响应和原 Entry 顺序 |
| L02 链路 failover | Transport Submit → 显式链路错误 → 记录健康/排空 → 选择未尝试 ACTIVE Channel → 完整原始 subBatch 重发 | 至少两个 ACTIVE Channel | 不同 handle，完整原始请求被重发，最终结果来自最终有效响应 |
| L03 Store 超时 failover | Store/BATCH_STORE Submit → CQE_IO_TIMEOUT → LINK_FAILURE → 选择未尝试 ACTIVE Channel → 完整原始 subBatch 重发成功 | STORE/BATCH_STORE 与至少两个 ACTIVE Channel | 发送次数为 2，第二次 Channel 不同，最终 Entry/任务 OK |
| L04 连接恢复 | ReportFailure → DRAINING → RECONNECTING → 成功或 FAILED/backoff → 新 generation ACTIVE | 达到错误阈值的 Channel | 旧对象不被强行删除；新 generation 可选取，失败状态与退避可观察 |
| L05 探针（共享模型） | ClientProbeScheduler → 有限 Transport/Channel 游标窗口 → ProbeTarget 空闲 ACTIVE/代际检查 → PROBE 互斥与全局 Lease → KeepAlive → 三态结果 → 释放 Lease/互斥 | QP 无业务 inflight、无未完成 PROBE，Client 在途未达 probeMaxInflight | 忙 QP 不发送；周期不重叠；扫描/提交/在途不越界；显式链路错误排空；完成、超时、取消后均可再次探测 |
| L06 流控 | busy 响应 → Group 预算下降 → 准入检查 → 合格成功响应 → 预算上升 | flowControlEnabled=true、Group 已配置 normal/busyFloor | `currentLimit`、congested、Group inflight 和最终准入结果符合公式 |
| L07 MR 生命周期 | RegisterRegions → StoreAsync → 未完成任务 → UnregisterRegions → 完成回调 → 再次注销 | 已注册 MR、任务使用对应 Handle | 忙时整批拒绝且无物理注销；完成后成功注销 |
| L08 Query 结果 | QUERY Submit → CQE_KEY_NOT_EXIST 或正常结果 Buffer → Entry 状态归一化 → 聚合 | QUERY 操作 | 顶层 OK，exists 按 Entry 映射，不误报链路错误或部分失败 |

| L09 FLOW_WAIT | Transport Submit → TryAcquire 满负载 → FLOW_WAIT/Group CV 等待 → inflight 释放 → 重新准入 → Send/CQE | ACTIVE Channel 已满且 flow_wait 开启 | 释放后成功发送；不释放则按 Deadline TIMEOUT，且不产生 Send |
| L10 逻辑 Slot 与 CID | SQE 构建分配 CID → BindAttemptCid → 重试分配新 CID/attemptId → logicalSlotId+generation 校验 → 确认释放或未确认 Quarantine | 逻辑 Slot 在恢复时复用，generation 更新；CID 活跃集合非空 | 旧响应不误完成，回绕不复用活跃 CID，未确认资源不被提前复用 |
| L11 健康恢复 | GetHealthSnapshot → 失败排空 → RED/YELLOW → RecoverLoop 新 generation → GREEN | 至少两个 QP，故障达到阈值 | active/draining/reconnecting/failed 数量和健康状态正确，logicalSlotId 不变 |
| L12 Wait 取消 | ClientTask 排队或 Transport 已提交 → Wait 超时 → 设置 cancelRequested → Process/Dispatch/Retry 停止新 attempt → Quarantine/Shutdown | ClientTask 已提交但尚未完成 | Wait 返回 TIMEOUT，排队任务不再 Dispatch，未确认 MR/Slot 不被提前注销 |

| L13 PROBE 重试与退避 | PROBE 首轮超时 → HandleAttemptFailure 设置 retryAt → 到期后 ExecuteRetry 原目标 QP 新 CID → 预算计数 → 成功或耗尽释放 Lease | probeRetryCount>0，目标 QP ACTIVE 且空闲 | 重试不增加业务 inflight；预算包含首轮和 m 次重试；成功后保持 ACTIVE，预算耗尽不发送 |

## 5. 默认开关与未完成范围

以下是当前实现与 Story 完整目标之间必须保留的边界，不应被“全量软件测试通过”掩盖：

1. **默认开关与发布迁移**：`probeEnabled=false`、`flowControlEnabled=false`、`connectRetryPerRound=0`，用于保持现有业务行为；需要显式配置开启。Story 目标中的默认开启/K=2 尚未作为默认行为切换，共享调度器已落地但默认不自动启用。
2. **探针轮内重试与退避**：`probeRetryCount/probeRetryBackoffMs` 已接入，`retryAt` 未到期不发起新 attempt；当前默认 `probeRetryCount=0` 不额外重试，`probeRetryBackoffMs=5`，所有首轮和 m 次重试均受 `probeMaxSubmissionsPerRound` 限制。
3. **FLOW_WAIT 与默认策略**：FLOW_WAIT 已实现，但只在 `flowControlEnabled=true` 且 `channelFullPolicy=flow_wait` 时启用；默认 `flowControlEnabled=false`、`channelFullPolicy=fail_fast`，因此默认满负载仍返回连接错误，不自动等待。`NO_ACTIVE` 永远不进入 FLOW_WAIT。
4. **MR/Slot/CID 隔离**：未确认 Send/Flag Slot、CID 和 MR 句柄已进入 Executor 级 Quarantine，任务移除后仍受保护；当前 Provider 没有 drain-proof API，所以运行期不提前释放，统一在 Shutdown 清理。该策略可能使小容量池或 CID 空间耗尽并返回 `RESOURCE_BUSY`，不等于 Provider 已证明硬件 IO 完成。
5. **稳定逻辑 Slot**：已实现 Group 内 `logicalSlotId`，恢复复用 Slot 并递增 generation；`ConnectionAttemptKey(groupId,logicalSlotId,generation)` 用于换链排除和响应校验。

7. **通用超时兼容性**：普通 task-deadline 仍保持既有 `TIMEOUT` 语义；`CQE_IO_TIMEOUT` 已统一按 LINK_FAILURE 换链，不再提供单独的公共结果状态或按操作类型的超时 veto。
